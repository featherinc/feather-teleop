Meta Quest Hand: start here

You move the controllers. The AGX does the maths. The robot follows.

Robot models are not included. Supply the matching URDF separately. A new AGX also needs its robot software installed.
Use the matching FeatherSDK and its working CAN/Teensy setup. Camera video also needs the ZED SDK. These installations are not in the ZIP.

First: unzip the two files

These are two normal ZIP files. No numbered parts, joining, or scripts are needed.

  1. Download albert_meta_quest_hand.zip, Unity_Meta_Quest_Project.zip, and this guide.
  2. On Windows, right-click each ZIP and choose Extract All.
  3. On Linux / Ubuntu, right-click each ZIP and choose Extract Here, or open it in your archive manager and click Extract.
  4. You get albert_meta_quest_hand/ and My project/. Use new destination folders to avoid replacing existing files. Continue below.

The AGX ZIP is about 78 MB. The Unity ZIP is about 28 MB. Both are below 100 MB per file. An AGX without a desktop can use its normal unzip command; no supplied script is required.

2. Set it up

  1. Unzip the AGX ZIP. Put its meta_quest_hand and configs folders inside /home/feather/Workspace/featheros/showcase/team/albert/. Supply the matching URDF_C_Arm_03_description-20260625T192804Z-3-001 model folder separately beside them, including the full/left/right URDFs and referenced meshes. It is no longer bundled. Section 2 cannot load IK without it. Back up existing folders before replacing anything.
  2. Install the Quest app. Inside the unzipped folder, find QuestAGXPoseHandModes.apk. Install it with Meta Quest Developer Hub, or use adb install -r "QuestAGXPoseHandModes.apk" with USB debugging allowed.
  3. Join the same Wi-Fi. Connect the Quest and your PC to JetsonCamNet. This app sends to the AGX at 10.42.0.1. No internet is needed during teleoperation.
  4. Open the notebook on the AGX. Use meta_quest_hand/meta_quest_hand.ipynb and the working FeatherSDK Python kernel. Read Settings first. The saved copy has RUN_HARDWARE=True; initialization can move/calibrate hardware. Use False for a model-only preview.
  5. Run the numbered sections in order. Section 2a is optional video; section 3.1 is optional manual homing. Run the other setup cells, then section 7. Use only one live robot notebook at a time.

3. Start and stop

Open Quest AGX Pose. Wait for READY. Hold your neutral controller/head pose. Press right A to start; the arms first move to their zero-joint reference. Press A again to home and disable the arms. Wait for READY before starting again.

How it works

Extra setup: camera, Unity, and missing software

AGX software: The matching FeatherSDK, its dependencies and native communications bridge must already work. The code expects a valid /feathersys/configs/infra/comms_manager_conf.py. The loose file with that name is a reference copy; do not blindly overwrite another robot's configuration. Check motor IDs, CAN wiring, limits, and calibration for the receiving robot.

Python: The notebook uses NumPy, SciPy, Pinocchio (robotics), pandas, and Jupyter/ipykernel, plus FeatherSDK's dependencies. Video also uses Pillow and pyzed.sl. The package does not pin a complete environment.

Camera: Copy quest_zed.py and quest_zed_worker.py into /home/feather/Workspace/featheros/TeleVision/teleop/. The rest of TeleVision is not needed for this camera path. Section 2a expects /home/feather/Workspace/featheros/TeleVision/.env-quest/bin/python with the camera dependencies. It selects ZED 2i serial 35928961; change that setting for another camera. Pose input uses UDP 5005; video uses TCP 5006.

Unity: Extract the Unity ZIP, then use Unity Hub to add the My project folder. Open with 6000.3.6f1 and Android Build Support. Internet is needed the first time to restore Unity packages (Meta XR 83.0.4). The saved build scene is Assets/_Recovery/0 (5).unity. Both pose and video scripts are attached. The ZIP includes Assets (and .meta files), Packages, and ProjectSettings, except the unused Assets/Free Pack audio collection. The spoken hand-mode clips in Assets/Resources/FingerSelection are kept. One older recovery scene (0 (13).unity) loses a sound reference; the active build scene does not use those audio files. Cache/build folders are omitted; Unity regenerates them. All retained files are unchanged. The original Unity project was not modified, and no new APK was built.

Find the code: After extracting the AGX ZIP, read meta_quest_hand/NOTEBOOK_FILE_GUIDE.md for the section-to-file map. Session logs go in meta_quest_hand/recordings/live/.
